Product Thinking, Prompt-Led Development & AI Quality

I shaped Vidhu Astro Prediction from a product and business perspective: defining the user journey, functional requirements, calculation outputs, report experience and expected behaviour. I used structured natural-language prompts and iterative instructions to AI coding assistants to generate, modify and debug application code, then reviewed the output and tested the resulting workflows. From a quality perspective, the application separates deterministic astronomical calculations from Gemini-generated explanations: Python and Swiss Ephemeris produce the structured Fact Pack, classical reference lookup adds relevant context, and the Gemini workflow generates English or Tamil narratives. Rule-based checks compare selected output fields with computed facts and can trigger a bounded correction path.

Layer 1: Math Engine

Calculation layer: Python and Swiss Ephemeris (pyswisseph) are used for planetary positions, house cusps and Dasa calculations. This layer provides deterministic values separately from generated narrative text.

Layer 2: Classical Knowledge Retrieval

Reference lookup: Key-based retrieval attaches relevant classical slokas (including material from Jathaka Alankaram) to the computed Fact Pack. This is a structured lookup approach, not a claim of a vector-database RAG implementation.

Layer 3: Gemini Interpreter

Prompted generation: The Gemini API receives structured context and prompts to produce contextual interpretations in English and Tamil. Outputs are reviewed against the supplied facts and expected behaviour.

Layer 4: Rule-Based Validation

Quality validation: Rule-based Python checks compare selected generated fields with the Fact Pack without another LLM call. A mismatch can trigger structured correction feedback through a bounded retry path (maximum two retries).

⚡

Model Availability & Fallback

Model-selection and fallback handling help the application respond to unavailable or changed Gemini model endpoints. This supports resilience against model-version changes and endpoint errors.

🛡️

API Error & Retry Handling

Failure-path checks cover API responses such as 404, 429 and 503. Retry and backoff behavior is used to handle transient errors and rate limits while avoiding uncontrolled repeated requests.

💾

Usage State & Quota Tracking

SQLite-based usage tracking records request and quota-related state. WAL mode supports the application's database access pattern; quota checks help manage API usage and reduce avoidable request failures.

TEAM CAPSTONE PROJECT

Campaign Performance Analytics & ROI Modeling

Analyzed 200,000 campaign records across five companies (full year 2021) using ANOVA, regression and exploratory analysis in KNIME and Excel, to test whether timing and other factors actually move ROI.

  • Hypothesis testing: Ran one-way ANOVA on 11 factors against ROI. None was significant at 5%; time pattern (p = 0.067) and location (p = 0.058) came closest.
  • ROI model: Linear regression reached R2 = 0.89, driven almost entirely by profit and acquisition cost. Timing variables added no significant explanatory power.
  • Volume vs. efficiency: The morning slot holds 50% of total profit, but also 50% of campaigns, so profit per campaign is flat across time slots.
  • Tooling: Compared KNIME and Excel on 200K rows; KNIME handled the volume and regression where Excel stalled.

The R2 of 0.89 comes from profit and acquisition cost, which are mechanically tied to ROI (ROI is roughly profit ÷ cost, about 5×). Frequency, location, time pattern and impressions all have |t| below 1.4. Honest takeaway: this dataset shows no evidence that timing changes ROI.

Analyst recommendations

  • Do not reallocate budget by time slot on this evidence. Per-campaign profit and ROI are statistically indistinguishable across slots.
  • Test timing properly. Run controlled A/B experiments with matched audiences and hold-outs, instead of comparing aggregates.
  • Re-fit the model on timing and audience features only. Removing profit from the predictors would show whether any real signal exists.
  • Improve conversion quality rather than spend alone. Conversion rate is flat at about 8% across every segment, so messaging and targeting are the open levers.
