ENTERPRISE AI AUDITING IN PRACTICE

Where Deterministic Code Decouples from the LLM

Language models inherently hallucinate mathematical coordinates, planetary cusps, and date boundaries. Vidhu Astro implements a strict separation of concerns: Python and the Swiss Ephemeris compute ground-truth astronomy first, creating an immutable Fact Pack. The LLM functions strictly as a linguistic narrator, guarded by automated retry logic and cancellation business rules (e.g., Kemadruma Yoga cancellation logic, Natal-First prioritization).

Layer 1: Math Engine

Deterministic Classical Base: Python + Swiss Ephemeris (pyswisseph) calculates planetary degrees, house cusps, and Vimshottari Dasa dates. The LLM never computes math.

Layer 2: RAG Researcher

Classical Knowledge Lookup: Key-indexed retrieval attaching verified classical slokas (e.g., Jathaka Alankaram) to the Fact Pack based strictly on computed planetary positions.

Layer 3: Gemini Interpreter

Constrained Generative Narrator: Receives only the verified Fact Pack. Formulates contextual, bilingual interpretations in English and Tamil without inventing astronomical facts.

Layer 4: Zero-Token Critic

Autonomous QA Audit: Plain-Python validation running at zero LLM token cost. Cross-references output against the Fact Pack; triggers targeted revisions (max 2 retries) on mismatch.

Automated Model Discovery

Dynamic fallback orchestrator that probes available Gemini endpoints, mitigating breaking changes when specific model versions are deprecated by Google.

HTTP 404 & 429 Jitter Backoff

Exponential backoff with randomized jitter to handle upstream rate limits and transient gateway timeouts without degrading user sessions.

SQLite WAL State & Quota Tracking

Write-Ahead Logging (WAL) mode enables concurrent reads and writes, enforcing daily API call quotas and state isolation per user request.

TEAM CAPSTONE PROJECT

Campaign Performance Analytics & ROI Modeling

Analyzed 200,000 campaign records across five companies (full year 2021) using ANOVA, regression and exploratory analysis in KNIME and Excel, to test whether timing and other factors actually move ROI.

  • Hypothesis testing: Ran one-way ANOVA on 11 factors against ROI. None was significant at 5%; time pattern (p = 0.067) and location (p = 0.058) came closest.
  • ROI model: Linear regression reached R2 = 0.89, driven almost entirely by profit and acquisition cost. Timing variables added no significant explanatory power.
  • Volume vs. efficiency: The morning slot holds 50% of total profit, but also 50% of campaigns, so profit per campaign is flat across time slots.
  • Tooling: Compared KNIME and Excel on 200K rows; KNIME handled the volume and regression where Excel stalled.

The R2 of 0.89 comes from profit and acquisition cost, which are mechanically tied to ROI (ROI is roughly profit ÷ cost, about 5×). Frequency, location, time pattern and impressions all have |t| below 1.4. Honest takeaway: this dataset shows no evidence that timing changes ROI.

Analyst recommendations

  • Do not reallocate budget by time slot on this evidence. Per-campaign profit and ROI are statistically indistinguishable across slots.
  • Test timing properly. Run controlled A/B experiments with matched audiences and hold-outs, instead of comparing aggregates.
  • Re-fit the model on timing and audience features only. Removing profit from the predictors would show whether any real signal exists.
  • Improve conversion quality rather than spend alone. Conversion rate is flat at about 8% across every segment, so messaging and targeting are the open levers.
